## 1. 先搞清楚：什么是"结构化输出"？

### 1.1 一句话解释

**结构化输出 = 让大模型按照程序能理解的格式（如 JSON）返回数据，而不是自由发挥写一大段话。**

### 1.2 举个例子

假设你问 AI："介绍一下爱因斯坦"。

**普通输出（非结构化）：**

```text
阿尔伯特·爱因斯坦（Albert Einstein，1879年3月14日—1955年4月18日），
出生于德国，是20世纪最伟大的物理学家之一。他提出了相对论...
```

这段文字人类看得懂，但程序想提取"出生年份"就非常困难——需要用复杂的正则表达式去匹配。

**结构化输出：**

```json
{
  "name": "阿尔伯特·爱因斯坦",
  "birth_year": 1879,
  "nationality": "德国",
  "famous_theory": "相对论"
}
```

程序可以直接用 `result.birth_year` 拿到数字 1879，简单直接！

### 1.3 类比理解

| 场景     | 非结构化                          | 结构化                                  |
| -------- | --------------------------------- | --------------------------------------- |
| 快递单   | 一段手写文字"张三，北京朝阳区..." | 表格：姓名、电话、地址、邮编            |
| 简历     | 一篇自我介绍文章                  | JSON：{姓名、年龄、技能数组、工作经历}  |
| 天气预报 | "今天天气不错，有点热"            | JSON：{温度: 28, 湿度: 65%, 天气: "晴"} |

## 2. 为什么纯靠 Prompt 不靠谱？

很多初学者第一反应是："我在问题里写清楚'请用 JSON 格式返回'不就行了？"

**答案是：不够。** LLM 虽然会尽量配合，但它本质上是一个"文本生成器"，不是"数据库查询器"。它会"自由发挥"，导致以下问题：

### 2.1 四大痛点

| 痛点              | 说明                                   | 示例                                       |
| ----------------- | -------------------------------------- | ------------------------------------------ |
| **包裹 markdown** | LLM 习惯用 ` ```json ` 代码块包裹 JSON | ` ```json\n{"name":"张三"}\n``` `          |
| **前后加废话**    | LLM 喜欢先解释再给出答案               | "好的，以下是信息：\n\n{"name":"张三"}"    |
| **字段名乱写**    | 不严格按照你要求的字段名               | 你要 `birth_year`，它写 `出生年份`         |
| **类型不确定**    | 数字可能变成字符串                     | `article_count` 本应是 `15`，但返回 `"15"` |

### 2.2 手动解析的痛苦

如果不用结构化输出工具，你的代码会变成这样：

````javascript
// 去掉 markdown 代码块
const match = content.match(/```(?:json)?\s*([\s\S]*?)\s*```/);
const json = match ? match[1] : content;

// 解析 JSON
try {
  const data = JSON.parse(json);
} catch (e) {
  // 解析失败！LLM 可能返回了不合法 JSON
}

// 还要手动做类型转换
const count = parseInt(data.article_count); // 不确定是不是数字
````

**这太痛苦了！** 每个接口都要写一堆解析逻辑，而且很容易出错。

## 4. 第1站：最原始的方式——纯靠 Prompt

> 配套代码：`01-normal.mjs`

### 4.1 核心思路

直接在 Prompt（问题）里写明："请用 JSON 格式返回，包含以下字段..."

### 4.2 代码示例

````javascript
const question = `请介绍抖音博主"造船的路飞"的信息。
要求以 JSON 格式返回，包含以下字段：
- name：姓名（字符串）
- birthday：生日（字符串）
- article_count：文章数量（数字）
...`;

const res = await model.invoke(question);
// res.content 是 LLM 返回的原始文本

// 手动处理：去掉 markdown 代码块、解析 JSON、类型转换...
let content = res.content;
const codeBlockMatch = content.match(/```(?:json)?\s*([\s\S]*?)\s*```/);
if (codeBlockMatch) content = codeBlockMatch[1].trim();
const jsonResult = JSON.parse(content);
````

### 4.3 问题总结

- **格式不确定**：可能被 markdown 包裹，可能有废话
- **类型不保证**：数字可能变字符串
- **维护成本高**：每个接口都要手写解析逻辑

**这一站的意义**：让你亲身体验"没有工具辅助时有多痛苦"，后续才能理解工具的价值。

## 5. 第2站：JsonOutputParser——自动提取 JSON

> 配套代码：`02-json-output-parser.mjs`

### 5.1 核心思路

LangChain 提供了一个 `JsonOutputParser`，它能自动从 LLM 的输出中提取 JSON。

### 5.2 Output Parser 是什么？

你可以把它想象成**快递的"包装+拆包"服务**：

- **寄件时**：给包裹贴上"请按此格式填写"的标签
- **收件时**：自动拆包，把内容整理成程序能用的格式

### 5.3 代码示例

```javascript
import { JsonOutputParser } from "@langchain/core/output_parsers";

const parser = new JsonOutputParser();

// 在 Prompt 末尾附加格式化指令
const question = `介绍...\n${parser.getFormatInstructions()}`;

const res = await model.invoke(question);

// 自动提取并解析 JSON！不需要手写正则
const jsonResult = await parser.parse(res.content);
```

### 5.4 重要警告

**在 `@langchain/core` 较新版本中，`JsonOutputParser.getFormatInstructions()` 返回空字符串 `""`，这个方法已经失效。**

但它仍然有价值：

- `parser.parse()` 仍然可以自动提取 JSON（去掉 markdown 代码块等）
- 了解它的演变过程，有助于理解为什么需要更好的方案

## 6. 第3站：StructuredOutputParser（简单版）

> 配套代码：`03-structured-output-parser-names.mjs`

### 6.1 核心思路

`StructuredOutputParser` 是 `JsonOutputParser` 的升级版：

1. 你告诉它"我想要哪些字段"
2. 它**自动生成**一段详细的格式化指令
3. 你把指令拼到 Prompt 里发给 LLM
4. LLM 返回后，Parser 自动解析

### 6.2 最简单的方式：fromNamesAndDescriptions

```javascript
import { StructuredOutputParser } from "@langchain/core/output_parsers";

const parser = StructuredOutputParser.fromNamesAndDescriptions({
    name: "博主的姓名",
    birthday: "博主的生日，格式如 1990-01-01",
    article_count: "发布的文章总数",
    // ... 更多字段
});

// 自动生成格式化指令
const formatInstructions = parser.getFormatInstructions();
// 会返回类似：
// "You must format your output as a JSON value...
//  Here is the JSON Schema instance your output must adhere to..."
```

### 6.3 优缺点

| 优点                            | 缺点                       |
| ------------------------------- | -------------------------- |
| 代码极简，几行搞定              | **所有字段默认都是字符串** |
| 自动生成格式指令，Prompt 更干净 | 无法进行严格的类型校验     |
| 适合快速原型                    | 复杂数据结构不够用         |

**关键知识点**：`fromNamesAndDescriptions` 的设计初衷是"快速验证想法"，但它只知道"字段名+描述"，不知道类型信息。所以 `article_count` 虽然你暗示是数字，LLM 仍可能返回 `"15"`（字符串）。

## 7. 第4站：StructuredOutputParser + zod（推荐）

> 配套代码：`04-structured-output-parser-zod.mjs`

### 7.1 zod 是什么？

**zod 是一个 TypeScript 优先的 Schema 声明和校验库。**

打个比方：

- **没有 zod**：你告诉 LLM "给我一个人的信息"，它可能返回任何东西
- **有 zod**：你画了一张"蓝图"，上面精确标注了 "name 是字符串、age 是数字、hobbies 是字符串数组"，LLM 按图施工，zod 最后验收

### 7.2 为什么 zod 特别适合 AI 应用？

1. **声明式**：用代码描述数据形状，而不是写文档
2. **类型安全**：TypeScript 自动推断类型，IDE 有代码提示
3. **运行时校验**：数据进来后自动检查是否符合预期
4. **描述能力**：`.describe()` 会被 LangChain 提取到 Prompt 中

### 7.3 代码示例

```javascript
import { z } from "zod";
import { StructuredOutputParser } from "@langchain/core/output_parsers";

// 用 zod 定义精确的输出结构
const schema = z.object({
    name: z.string().describe("博主的姓名"),
    birthday: z.string().describe("生日，格式如 1990-01-01"),
    gender: z.enum(["男", "女"]).describe("性别"),
    article_count: z.number().describe("文章总数，必须是数字"),
    follower_count: z.number().describe("粉丝数量，必须是数字"),
    main_articles: z.array(z.string()).describe("主要文章标题列表")
});

// 从 zod schema 创建 Parser
const parser = StructuredOutputParser.fromZodSchema(schema);

// 自动生成包含完整类型信息的格式化指令
const formatInstructions = parser.getFormatInstructions();
```

### 7.4 zod 常用类型速查

| 类型            | 说明   | 示例                                       |
| --------------- | ------ | ------------------------------------------ |
| `z.string()`    | 字符串 | `z.string().describe("姓名")`              |
| `z.number()`    | 数字   | `z.number().describe("年龄")`              |
| `z.boolean()`   | 布尔值 | `z.boolean().describe("是否激活")`         |
| `z.array(X)`    | 数组   | `z.array(z.string()).describe("标签列表")` |
| `z.object({})`  | 对象   | `z.object({name: z.string()})`             |
| `z.optional()`  | 可选   | `z.string().optional()`（字段可以不存在）  |
| `z.enum([...])` | 枚举   | `z.enum(["男", "女"])`（只能是列出的值）   |

### 7.5 核心优势

```javascript
const result = await parser.parse(res.content);

// 现在你可以 100% 信任这些类型：
result.article_count  // 一定是 number，可以直接做数学运算
result.main_articles  // 一定是 string[]，可以直接调用 .join()

// 如果 LLM 返回了字符串 "15" 而不是数字 15，
// parser.parse() 会抛出 ZodError，告诉你哪里不对
```

### 7.6 对比：fromNamesAndDescriptions vs fromZodSchema

| 特性            | fromNamesAndDescriptions | fromZodSchema                  |
| --------------- | ------------------------ | ------------------------------ |
| 字段类型        | 全是字符串               | string、number、array、enum 等 |
| Schema 校验     | 无                       | 有（运行时自动校验）           |
| TypeScript 推断 | 无                       | 有                             |
| 适用场景        | 快速原型                 | 生产环境                       |

## 8. 第5站：withStructuredOutput（最现代、最推荐）

> 配套代码：`05-with-structured-output.mjs`

### 8.1 终极简化

这一站是**最推荐**的生产环境方案，因为它：

- 不需要手动拼接 `getFormatInstructions()`
- 不需要手动调用 `parser.parse()`
- 不需要关心 LLM 返回的是字符串还是 JSON
- **一行代码搞定**：`model.withStructuredOutput(schema)`

### 8.2 代码示例

```javascript
import { z } from "zod";

// 1. 定义 schema（和上一节一样）
const schema = z.object({
    name: z.string().describe("姓名"),
    birth_year: z.number().describe("出生年份"),
    // ...
});

// 2. 核心魔法：一行代码创建结构化模型
const structuredModel = model.withStructuredOutput(schema);

// 3. 直接调用！不需要格式指令，不需要 parse()
const result = await structuredModel.invoke("介绍一下爱因斯坦");

// result 直接就是解析好的对象！
console.log(result.name);        // "阿尔伯特·爱因斯坦"
console.log(result.birth_year);  // 1879（number 类型）
```

### 8.3 底层原理：Function Calling

**为什么 withStructuredOutput 这么强？**

现代 LLM（如 GPT-4、GPT-3.5-turbo）支持 **Function Calling**（函数调用）能力。这意味着模型可以直接返回结构化的 JSON 对象，而不是自由文本。

LangChain 的 `withStructuredOutput` 就是利用了这个能力：

1. 把你的 zod schema 转换成 OpenAI 的 function schema
2. 调用模型时，传一个特殊的 `tools` 参数
3. 模型被"强制"返回符合 schema 的 JSON
4. LangChain 自动解析 JSON 并做 zod 校验
5. 最终直接返回解析好的对象

**对比之前的方案：**

```
之前（第4站）：Prompt + 期望 + 祈祷 → LLM 返回文本 → 提取 JSON → 校验
现在（第5站）：模型直接返回结构化数据（function calling）→ 校验 → 直接给对象
```

因为是在**模型层面**就被约束了，所以准确率比 Prompt 工程高得多！

### 8.4 两种模式

| 模式                             | 用法                                                         | 适用场景                          |
| -------------------------------- | ------------------------------------------------------------ | --------------------------------- |
| **默认模式**（function calling） | `model.withStructuredOutput(schema)`                         | 模型支持 function calling（推荐） |
| **JSON 模式**                    | `model.withStructuredOutput(schema, { method: "jsonMode" })` | 模型不支持 function calling       |

## 9. 第6站：XMLOutputParser（拓展知识）

> 配套代码：`06-xml-output-parser.mjs`

### 9.1 为什么需要 XML？

前面的章节都在讲 JSON，但 JSON 不是唯一选择。

**XML（可扩展标记语言）** 是另一种结构化数据格式：

```xml
<person>
  <name>张三</name>
  <age>25</age>
</person>
```

### 9.2 什么时候用 XML？

1. **数据有嵌套层级关系时**，XML 可读性更好
2. **需要给元素添加属性时**（如 `<book id="123">`）
3. **需要混合文本和结构化数据时**
4. **某些传统系统**（如企业级 Java 系统）更习惯 XML

### 9.3 代码示例

```javascript
import { XMLOutputParser } from "@langchain/core/output_parsers";

const parser = new XMLOutputParser();

const question = `请提取人物信息...\n${parser.getFormatInstructions()}`;

const res = await model.invoke(question);
const result = await parser.parse(res.content);
```

### 9.4 注意事项

XML 解析后的数据格式比较特殊：

```xml
<!-- XML 输入 -->
<person>
  <name>张三</name>
  <age>25</age>
</person>
```

```javascript
// 解析后
{
  person: {
    name: ["张三"],  // 注意：文本被包装成数组！
    age: ["25"]
  }
}
```

**访问时要取 `[0]`**：`result.person.name[0]`

### 9.5 小结

- 除非有明确的 XML 需求，否则**优先使用 JSON**
- JSON 更轻量、更流行、生态系统支持更好

## 11. 常见问题 FAQ

### Q1: 我的模型不支持 function calling，怎么办？

**A**: 退回到第4站（`StructuredOutputParser.fromZodSchema`），它通过 Prompt 工程实现结构化输出，不依赖模型的 function calling 能力。

### Q2: withStructuredOutput 报错"模型不支持 function calling"？

**A**: 两种可能：

1. 你的模型确实不支持（如某些 GPT-3.5 的免费版本）
2. 你的 API 代理/中转服务拦截了 function calling 请求

解决方案：改用 JSON 模式

```javascript
const structuredModel = model.withStructuredOutput(schema, {
  method: "jsonMode"
});
```

### Q3: LLM 返回的数据不符合 zod schema，parse() 报错了？

**A**: 这是**好事**！说明校验在工作。没有校验的话，这类错误会在更隐蔽的地方爆发（比如用户看到奇怪的数据）。

解决方案：

1. 优化 `.describe()` 的描述，让 LLM 更清楚要求
2. 使用更强大的模型（GPT-4 比 GPT-3.5 更听话）
3. 给 Prompt 加 few-shot 示例

### Q4: number 类型的字段，LLM 为什么返回字符串？

**A**: 因为 LLM 本质上是"文本预测器"，它生成的是 token 序列，不是真正的数据类型。即使你用 `z.number()` 声明，LLM 仍可能生成 `"15"` 而不是 `15`。

**withStructuredOutput** 比 Prompt 工程更能解决这个问题，因为它在模型层面约束输出格式。

### Q5: 这些示例需要安装什么依赖？

**A**: 项目根目录已经配置好了，核心依赖：


### Q6: 我想在自己的项目里用，最小化的代码是什么？

**A**: 如果你使用支持 function calling 的模型：

```javascript
import { ChatOpenAI } from "@langchain/openai";
import { z } from "zod";

const model = new ChatOpenAI({ modelName: "gpt-4", temperature: 0 });

const schema = z.object({
  name: z.string(),
  age: z.number(),
});

const structuredModel = model.withStructuredOutput(schema);
const result = await structuredModel.invoke("介绍一下张三");

console.log(result);  // { name: "张三", age: 25 }
```

**只需要 10 行代码！**
