# 什么是 AI Agent：从大模型到智能体

## 一句话定义

**AI Agent（智能体）是一个以大语言模型为大脑、能够自主规划、调用工具、观察结果并持续迭代，最终完成用户目标的软件系统。**

它不是"更聪明的聊天机器人"，而是把 LLM 从"会说话的接口"升级成"能办事的员工"。

## 一个直觉例子

对比三种形态：

1. **纯 LLM 聊天**：用户说"帮我设计一个工作流"，模型只能回答"好的，我建议你这样设计……"，然后就没有然后了。
2. **固定工作流**：代码写死"解析输入 → 调接口 → 返回结果"，用户需求一变，代码就要改。
3. **AI Agent**：用户说"帮我设计一个工作流"，Agent 自己判断"信息不全，先问数据源"→ 拿到答案后规划节点 → 生成 JSON → 保存到平台 → 试运行 → 发现准确率只有 80% → 自动修改再验证 → 最终交付。

本项目（Coze 工作流自动生成 Agent）就是典型的第三种：它不是一个"生成 JSON 的接口"，而是一个能完成 **设计 → 生成 → 部署 → 试运行 → 验证 → 修复** 闭环的智能体。

## Agent 的四个组成要素

业界对 Agent 的拆解大同小异，可以归纳为四件套：

| 要素 | 作用 | 本项目的对应实现 |
| ---- | ---- | ---------------- |
| **大脑（LLM）** | 理解、推理、决策 | DeepSeek / ChatOpenAI 驱动的 ReAct Agent |
| **工具（Tool）** | 与外部世界交互的"手脚" | `plan_workflow`、`generate_workflow`、`save_to_coze`、`batch_validate` 等 11 个工具 |
| **记忆（Memory）** | 记住上下文、状态、历史 | `MemorySaver` checkpointer、`session.store`、`workflow-cache` |
| **环境（Environment）** | 反馈来源，Agent 据此迭代 | Coze 平台 API、用户澄清回答、试运行结果 |

### 大脑

LLM 负责所有"软"决策：需求是否完整、下一步该做什么、结果是否满意。它不擅长的是精确计算和稳定执行——这部分交给工具和代码。

### 工具

工具是 Agent 和真实世界之间的桥梁。没有工具的 Agent 只能"说"，有了工具的 Agent 才能"做"。工具不仅包括外部 API，还包括 Agent 内部的能力封装，比如本项目里 `clarify_question` 这个"问用户"的工具。

### 记忆

LLM 本身没有记忆——每次调用都是无状态的。Agent 通过把对话历史、中间产物（比如工作流 planId、workflowId）保存下来，才实现了"多轮协作"和"接着上次继续做"。

### 环境反馈

Agent 与脚本的本质区别在于**闭环**：做了动作之后要看结果，根据结果决定下一步。试运行失败 → 看错误 → 修改 → 再试，这个循环就是环境反馈驱动的。

## 与几个容易混淆的概念划清界限

### LLM 应用 ≠ Agent

一个"输入 prompt → 输出 JSON"的接口只是 LLM 应用。判断标准：**系统是否根据动作的结果自主决定下一个动作？** 是，才是 Agent。

### 工作流 ≠ Agent

工作流是**预先画好的流程图**，分支条件也是人设计的。Agent 是**运行中动态决策**——用户需求不同，Agent 走的路径就不同，甚至路径本身是 LLM 现场想出来的。

有意思的是，本项目用 Agent 来**生成**工作流：Agent 是"建造者"，Coze 工作流是"被建造的产品"。这也说明 Agent 和工作流不是二选一，而是可以互相嵌套的。

### 自动化脚本 ≠ Agent

脚本是"if-then"的确定性执行。Agent 的每一步都包含概率性推理，因此需要**校验、重试、上限保护**这些工程手段来兜底（见第 7 篇）。

## 什么时候需要 Agent，什么时候不需要

Agent 不是银弹，它有成本：token 消耗高、行为不确定、调试困难。

| 场景 | 推荐方案 |
| ---- | -------- |
| 固定流程、参数确定 | 普通 API / 工作流 |
| 流程固定但参数变化多 | 模板 + 少量 LLM 填充 |
| 需求开放、需要自主决策、要调多个系统 | Agent |
| 需求开放、但失败代价极高 | Agent + 人工审批节点 |

一个实用判断：**如果需求的输入输出空间你提前想得清楚，就不需要 Agent；如果连"怎么做"都要运行时决定，才轮到 Agent。**

## 核心要点

- Agent = 大脑 + 工具 + 记忆 + 环境反馈，四者缺一不可
- Agent 与脚本/工作流的区别在于**动态决策与闭环迭代**
- 判断一个系统是不是 Agent：看它会不会"根据动作结果自主决定下一个动作"
- 选型上要克制，Agent 的成本与不确定性只有在"路径不可预知"时才值得

## 延伸思考

- 你的业务里哪些流程是"看似固定，其实需求经常变"的？那可能就是 Agent 的机会。
- Agent 自主性越高，失败时的责任边界越模糊——这是产品设计问题，不只是技术问题。
